# 会话列表页改版说明（2026-11）

本次两件事：**界面丰富一点**、**工作区那一行后面加一个加号，基于这个工作区建会话**。
改动集中在 `harmony/entry/src/main/ets/pages/SessionListPage.ets`，配色 token 在
`harmony/entry/src/main/ets/common/Theme.ets`。

---

## 1. 为什么改

改之前列表页是这样的：一列纯文字行，行与行之间只有缩进区别 —— 工作区名后面跟着一个会话数，
对话行是「标题 + 相对时间」，选中态是一条几乎看不见的底色。信息都在，但：

- 看不出「现在有多少会话在跑」，要自己去数；
- 工作区和它下面的会话没有容器感，滚动时容易看串行；
- 状态（运行中 / 异常 / 空闲）只有运行中有一个小转圈，异常的会话和空闲的几乎没区别；
- 顶部「刷新 / 设备 / 设置」是三个纯文字，和「已连接」挤在同一行，层级不分明。

建会话的路径也不顺：点右下角「新会话」→ 面板里是「输入框 + 最近 4 个工作区」，
**要自己从最近工作区里认出目标目录**。会话一多、工作区一多，就得来回找。

## 3. 工作区后面的「＋」怎么用

```
改之前:  右下角「新会话」 → 面板 → 在「最近工作区」里找目录 → 选中 → 填标题 → 创建
改之后:  某个工作区右边的 ＋ → 面板 → 工作区已经锁定成一张卡片 → 填标题/选模式 → 创建
```

- ＋ 在每个工作区卡片标题的右侧（30vp 圆按钮，点击热区 30vp，和三角、标题互不干扰：
  三角只折叠、标题只折叠、＋ 只建会话，各自 `hitTestBehavior(HitTestMode.Block)`）。
- 点开后新建面板顶部标题变成「**在 SRM 里新建会话**」，工作区位置是一张**锁定卡片**
  （图标 + 名称 + 完整路径 + 「更换」按钮），不会再出现「最近工作区」那一串让人找。
- 想换工作区就点「更换」，卡片换回输入框 + 最近工作区列表。
- 创建成功后自动 `refresh()` 并直接打开新会话；取消、关闭、创建失败都不会留下锁定态。
- 原来的入口（右下角 FAB、宽屏左栏底部按钮）都还在，点它们就是没锁定工作区的普通新建。

## 5. 评审后一并修掉的问题

独立评审（另一个 agent 只读评审）挑出来的 High/Medium 问题，这次一并改了：

| 问题 | 后果 | 修法 |
|---|---|---|
| 列表 ForEach key 只拼了 `kind|key|展开|选中|state` | 新建会话后工作区上的数字不变、桌面端改名不生效、相对时间停住、组尾圆角留在旧行 | key 带上 `title/updatedAt/count/firstOfGroup/lastOfGroup` |
| 详情页消息 ForEach key 只有消息 id | 流式文字、「点开更多」/「收起」、全文加载可能是**原地改字段** ⇒ 界面不更新 | key 带上 `text.length/streaming/expanded/loadingFull/fullError.length` |
| 双栏切会话不清全文缓存 | 会话 B 里同 seq 的消息显示会话 A 的全文 | 切会话时 `fullTexts.clear()` / `expandedSeqs.clear()` |
| `sessionId/title/cwd` 三个 `@Prop` 都 `@Watch` 同一回调 | 切一次会话挂 3 次、发 3 组请求 | 只 watch `sessionId` |
| 「未分组」组的 + 把兜底字符串当 cwd | 会建出一个叫「未分组」的工作区 | 该组 + 退回普通新建（不锁工作区） |
| 「创建」没有 in-flight 保护 | 网络慢时连点建两条会话 | 加 `creating`，按钮「创建中…」并禁用 |
| 「取消」不清 `newTitle/newCwd` | 下次打开面板带着上次的标题/路径 | 一起清掉 |
| 新建成功后目标组可能还是折叠的 | 返回列表看不到新会话，以为没建成 | 成功后自动展开该组 |
| `CARD #1C1C1F` 与背景 `#111113` 对比度 1.11:1 | 深色底上卡片/分隔线基本看不见，卡片化白做 | `CARD` → `#202025`，`BORDER_SOFT` → `#2E3034` |
| `+` 只有 30vp、顶栏图标 34vp | 低于 40vp 的建议热区 | 加 `responseRegion` 把热区撑到 40vp（视觉尺寸不变） |

**仍然没改、需要真机才能定的**（评审标「待确认」）：

- 右下角 FAB 的外层是满屏 `HitTestMode.Transparent` 容器（沿用了改版前的写法），
  极端情况下一次点击可能既命中 FAB 又命中它下方的会话行 —— 要真机滚到底点一次才知道；
- `↻ ▤ ⚙` 这些图标是用 `Text` 画的，HarmonyOS Sans 里是否会渲染成 emoji/豆腐块，要真机看；
- 系统字体放到最大 + 320vp 时顶栏右侧那一簇（胶囊 + 三个图标）会不会挤掉标题。
  彻底的做法是把图标换 `SymbolGlyph($r('sys.symbol.*'))`，但需要真机确认资源名。

## 7. 2026-11-05 追加的四处改动

### 7.1 长内容不再硬截断，改成「点开看更多」

- 之前 `mergeDelta()` 里超过 4000 字就会把正文剪断并追加「…（内容过长，已截断）」，
  后面流式来的字还会接在这句话后面，读起来是坏的。
- 现在：**内存里永远是全文**；渲染层只显示前 1200 字（工具输出前 3 行），
  下面一个「…点开更多」，点开显示全文、再点「收起」回到预览。
- 桥接本来就只给预览（`truncated=true`）的消息，仍然走 `fullMessage(sessionId, seq)` 取全文，
  失败时保留重试提示。

### 7.2 消息正文可以长按复制

- 会话正文的 `Text` 统一加了 `.copyOption(CopyOptions.LocalDevice)`（用户消息、助手消息、
  工具输出预览/展开、轨迹视图各一处），长按就能选字/复制。
- 原来的「复制」小按钮保留（复制的是全文）。

### 7.3 日间 / 夜间两套主题

- `common/Theme.ets` 改成「两套配色 + Palette 的 static getter」：
  - 夜间 = 原来对齐桌面端那套深色；
  - 日间 = 同层级的浅色（卡片白底、文字 #1B1D22、强调蓝 #2F6FED，对比度按 AA 挑）。
- 设置页「主题」现在是 **夜间 / 日间 / 跟随系统** 三个选项，切了立刻生效并落盘；
  跟随系统会听 `onConfigurationUpdate` 的颜色模式。
- 实现方式：`common/ThemeController.ets` 把偏好写进 AppStorage，每次切换把 `themeTick` +1；
  页面里 `Palette.X` 全部换成 `this.pal('X')`（读一下 tick 建立依赖），
  列表页额外用 `ForEach([this.themeTick])` 包了一层做整页重建。
- 系统栏（状态栏/导航栏）颜色也跟着主题走，不再出现系统默认的白色。

### 7.4 全屏但不压通知栏（消掉上下白边）

- `EntryAbility` 启动时 `setWindowLayoutFullScreen(true)` + 系统栏透明 + 系统栏图标颜色按主题切换；
  再用 `getWindowAvoidArea` 量出状态栏 / 手势条高度，写进 AppStorage 的
  `topSafeVp` / `bottomSafeVp`，各页面根容器按这两个值留 padding —— 所以内容是铺满的，
  但标题不会被通知栏压住，底部也不会出现白条。
- 真机验证：见 `docs/screenshots/theme-night-list.jpeg`、`theme-day-list.jpeg`。

### 7.5 大肥鱼 Q 版女主背景 + 「透明度」

- 用 MiniMax 图像生成做了两张 9:16 的吉祥物壁纸（同一角色的夜/日两版：银蓝短发 Q 版女生
  抱着胖鱼玩偶），预处理成 1080×1920 并压了一层与主题同色的渐变蒙版
  （顶部不透明保证文字可读、底部露出角色），文件在

## 8. 2026-11-05 追加：首页「运行中」拆分 + 点开看明细

### 之前为什么不完全准

原来的「运行中」是 `runningCount()`：只数**会话树里 state=running 的一级对话**。三个漏点：

1. **子 Agent 不算**：子 Agent 在会话树里是「话题」这一层，之前只数对话层；
2. **会话树的状态可能滞后**：树里的 state 来自桥接的摘要缓存，而桌面端真正在跑的判定来自
   DSH 的 live 行（`row.running`）；
3. **排队/待确认完全没进这一格**：它们只在右上角「待办」总数里，看不到构成。

### 现在的数据来源（三层取并集）

- **桥接 `pending` 帧**：`count` / `running[]`（桌面端 live 行，最准）/ `questions[]`；
- **会话树**：`state=running` 的对话 + `state=running` 的话题（= 子 Agent）；
- 由 `count - 运行中 - 待确认` 得到**排队任务数**（桥接就是这么算 count 的）。

### 首页现在长什么样

- 概览中间那格变成「**运行中**」：大数字 + 运行中转圈 + 小字 `子N · 队M`；
- 点这一格（或点右上角红色待办角标）打开「**运行中的东西**」面板：
  - **正在执行 (n)**：一条一条会话，带 cwd，点进去直接打开该会话；
  - **子 Agent (n)**：状态 running 的话题，副标题是父会话；
  - **排队任务 (n)**：标题是排队的那句话，副标题「在「xx」里排队」，点进去到对应会话；
    手机只会去问「在跑的 + 最近 12 个会话」的队列，剩下的会在列表后面补一句
    「另外 N 条在更早的会话里」；
  - **待确认问题 (n)**：桌面端在等用户回答的会话。
- 面板里的行点一条就进对应会话（子 Agent 的行进的是子 Agent 自己的会话）。

### 已知边界

- `pending` 帧由桥接的「待办监听」广播，只有手机上报过推送 token 时桥接才开这个监听；
  拿不到实时帧时页面会退回「会话树里的 running」，数字可能略滞后。
- 排队任务明细是按会话逐个问的，没有全局队列接口；所以「队N」是精确总数，
  列表默认列出最可能的那批（在跑 + 最近 12 个会话）。

## 9. 2026-11-05 追加：工作区按「最近有运行过任务」排序

### 之前的逻辑

- 组内按会话 `updatedAt` 倒序；
- 组间取组内最大的 `updatedAt` 倒序。

`updatedAt` 来自桥接 `session-tree`（桌面端每次跑任务都会更新这一行的 mtime），
所以「大体上」就是按最近活动排的。但有两个不明显的问题：

1. **正在跑的工作区不一定置顶**：如果桌面端还没把新的 mtime 刷进列表，它可能暂时排在后面；
2. **子 Agent 在跑不算**：子 Agent 是话题层，组内/组间排序完全没看它；
3. 界面上**看不出排序依据**，所以会有「不知道是不是按最近活动排」的疑问。

### 现在的规则（`buildRows()`）

1. 组里只要有「状态 running 的会话 / 状态 running 的话题(子 Agent) / 桥接实时 running 里的会话」，
   这一组的最近活动时间就记为 `now`，**直接排到最前面**；
2. 否则取组内最大的 `updatedAt` 作为最近活动时间，组间按它倒序；
3. 组内也一样：**在跑的排最前**，其余按 `updatedAt` 倒序；
4. 工作区标题行右侧新增「最近活动时间」（如 `刚刚` / `46 分钟前` / `11 天前`），
   和排序依据一致，一眼能对上。

真机截图：`docs/screenshots/workspace-sort.jpeg`（DSHHarmony 刚刚 → knowledge 46 分钟前 → SRM 54 分钟前 …）。

## 10. 2026-11-05 追加：修「背景图一直看不到」

改法：

- **背景图重新生成**（同一组角色原图）：蒙版从「顶部 0.94 → 底部 0.10」降到
  「顶部 0.42 → 底部 0.05」，月亮、星星、抱鱼的女主都看得清了（`mascot_night.jpg` / `mascot_day.jpg`）；

## 14. 2026-11-05 深夜：任务状态分色 + 「待处理」红标

### 桌面端有什么、缺什么

- 桌面端有：会话 **running / idle** 状态、`pending` 帧里的 **questions**(在等你回答的会话)；
- 桌面端**没有**「已读/未读」这个概念 —— 所以「已完成但还没看过」只能在手机本地记：
  存「上次看到这个会话的更新时间」，之后桌面端再更新这一行（跑完了、有新消息）就变成未读。

### 现在的状态色（列表里每条会话前面的小点）

| 颜色 | 含义 | 右侧标签 |
|---|---|---|
| 绿色 | 正在跑 | 转圈 |
| **红色** | 桌面端在等你回答/选择 | 「**待确认**」 |
| **琥珀色** | **已完成但还没看过**（有更新，你没点开） | 「**待看**」 |
| 灰色 | 空闲且已读 | 相对时间 |

### 右上角红色的数 = 真正需要你处理的

```
待处理 = 已完成待看(琥珀点) + 待确认问题(红点)
```

- 标题旁的红底「**待处理 N**」就是这个数，**App 图标角标也是同一个数**；
- 只有排队任务、没有需要你处理的时候，显示的是黄底的「排队 N」，不会占红色；
- 点红标/黄标都打开「运行中的东西」面板，里面多了「**已完成待看 (n)**」一节，点一条会进会话并**自动标成已读**。

### 实现要点

- 新增 `common/ReadStore.ets`：preferences 存 `{initialized, read: {sessionId: 上次看到的时间}}`，
  加载 / 标记已读 / 存盘；
- **第一次启动会建基线**（把当时所有会话标成已读），否则 1118 条会话全是未读；
- 打开会话（列表点进去、详情页从通知深链进入、活动面板点）都会 `markRead`；
- 列表返回时 `onPageShow` 重新拉一次，琥珀点/待处理数立刻更新；
- 未读状态只影响显示，不做任何桌面端写操作。


### 真机验证（2026-11-05 01:58）

1. 首页出现红底「● 待处理 1」，「更新本机知识库及新增内容」这条的点和右侧标签变成
   **琥珀点 + 「待看」** —— 截图 `docs/screenshots/unread-attention.jpeg`；
2. 点进这条会话再返回：**「待处理」红标消失**（退回黄色「排队 2」），那一行的琥珀点也没了
   —— 说明「打开即已读」和角标同步都生效 —— 截图 `docs/screenshots/unread-cleared.jpeg`。

另外补了两个细节：
- 会话页 `aboutToDisappear` 会再标一次已读（避免「正在看的时候桌面端又写了一句」被算成未读）；

## 16. 2026-11-05 凌晨：待看/待处理改成严格口径

反馈：**「还没跑完、消息还在生成」不能算待看；后台任务也不算；只有跑完了/在等我选择才算。**

### 旧口径的问题

`updatedAt > 上次已读时间` 就算待看 —— 但后台任务、流式写入都会改 mtime，
于是「还在生成」和「后台 job 写了点东西」都被误算成待看。

### 新口径（三道闸门，全部满足才算待看）

1. **必须观察到真正的结束事件**：上一轮状态是 `running`、这一轮不是（来自会话树/`sessions` 列表的对比），
   或者桥接 `pending` 帧里的 `finished[]`；
   —— 后台任务/流式写入只改 mtime，不会产生这个事件，所以不算；
2. **不能还在跑**：状态不是 running，且不在桥接实时 `running[]` 里；
3. **必须已经安静**：距离 `updatedAt` 至少 **15 秒**（还在生成/写消息的直接跳过）；
4. 结束事件时间必须晚于这个会话上次被打开看到的时间（`ReadStore` 里持久化）。

另外：**用户正看着这个会话时刚好结束的不算未读**（5 秒宽限）。

### 「待确认」才是唯一需要选择/回答的

- 红点「待确认」只来自桥接 `pending.questions`（桌面端 ask_user_question 在等你选）；
- 右上角红标「待处理」= 严格待看 + 待确认；图标角标同一个数。

### 代价（故意的）

如果手机在后台/离线期间恰好错过了整个 `running -> idle` 过程，那这次完成不会被补记成待看。
这是为「不误报」付出的代价；要补的话可以改成「连上后对最近 N 分钟结束的会话补一次」，但会重新引入误报风险。
